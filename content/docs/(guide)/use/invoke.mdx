title: Discover and invoke services
description: Search Varis for services, call them through the HTTP API, follow calls that take longer, retry safely, and handle every error.
---

An agent uses Varis in two steps: it searches for a service, and then it invokes the service. This page covers both through the HTTP API. 

If your agent uses MCP, the `search_services` and `invoke_service` tools do the same two things with the same rules, and `get_invocation` checks on a call.

Every request needs an agent key in the `Authorization` header. For more information, see [Headless agents](/use/agent-keys).

## Search for services

Send a `GET` request to `/v1/services`:

```bash
curl "https://api.usevaris.com/v1/services?q=convert+currency&max_price_cents=5" \
  -H "Authorization: Bearer $VARIS_AGENT_KEY"
```

The response lists the matching services in `data`. Choose one by its `description`, `instructions`, `price_usd`, and `input_schema`, and then copy its `id`. `price_usd` is what one call costs, including the 5% Varis fee, and `max_price_cents` filters on that same amount.

For every parameter and response field, see [Search published services](/reference/searchServices).

## Invoke a service

Send a `POST` request to `/v1/invocations`:

```bash
curl https://api.usevaris.com/v1/invocations \
  -H "Authorization: Bearer $VARIS_AGENT_KEY" \
  -H "Idempotency-Key: 5f0c2c1e-9b0e-4a77-8a52-3d1d1a2f0b6e" \
  -H "Content-Type: application/json" \
  -d '{
    "service_id": "var_serv_ydZfZ9gKKe1tQe",
    "input": { "from": "USD", "to": "EUR", "amount": 100 }
  }'
```

You always call Varis with `POST`, whatever method the service uses. Varis sends the input to the service the right way.

If the call succeeds, Varis returns `200`, and the service's result is in `output`:

```json
{
  "invocation_id": "var_invk_HgD8njwg3gkTca",
  "status": "success",
  "output": { "rate": 0.92, "converted": 92 },
  "completed_at": "2026-11-01T10:15:04.212Z",
  "request_id": "var_req_fc8e8702-6a7f-4f3f-9147-748936e5fee1"
}
```

For every field and response, see [Invoke a service](/reference/invoke).

You pay only for calls that succeed.

<Callout title="Moving from /v1/invoke">
`POST /v1/invoke` is deprecated. It still works, and takes the same request and returns the same responses as `POST /v1/invocations`. To move, change the path.
</Callout>

## Follow a call that takes longer

Some services take longer than 30 seconds. If the service tells Varis it has started, Varis returns `202` with `"status": "in_progress"`:

```json
{
  "invocation_id": "var_invk_HgD8njwg3gkTca",
  "status": "in_progress",
  "progress_percent": 40,
  "estimated_completion_at": "2026-11-01T10:27:00.000Z",
  "eta_in": "about 12 minutes",
  "provider_message": "Rendering frame 400 of 1000",
  "retry_after_seconds": 30,
  "instruction": "This call is still running. Retry POST /v1/invocations with the same service_id, input, and Idempotency-Key, or call GET /v1/invocations/var_invk_HgD8njwg3gkTca, after retry_after_seconds. Once returned, the output can be fetched again for one hour.",
  "request_id": "var_req_fc8e8702-6a7f-4f3f-9147-748936e5fee1"
}
```

To get the outcome, wait for `retry_after_seconds`, also sent as the `Retry-After` header, and then do either of the following:

- Look up the call by its ID:

  ```bash
  curl https://api.usevaris.com/v1/invocations/var_invk_HgD8njwg3gkTca \
    -H "Authorization: Bearer $VARIS_AGENT_KEY"
  ```

- Send the same request again, with the same `Idempotency-Key`.

Both return the same answer: `202` while the call runs, and then `200` with the output, or the error if it failed. Neither runs the call again or charges again. Any agent that belongs to your owner can look up the call.

`progress_percent`, `estimated_completion_at`, `eta_in`, and `provider_message` are what the service last reported. They appear once the service has said it started, and each is `null` until the service sets it.

A call that takes longer fails, and you aren't charged, in either of these cases:

- The service stops reporting on the call for 5 minutes.
- The call hasn't finished 24 hours after it started.

For every field, see [Get an invocation](/reference/getInvocation).

## Retry safely with an idempotency key

Every call needs an `Idempotency-Key` header. Use a new, unique value, such as a UUID, for each call you mean to make.

If your connection drops, retry the call with the **same** key. Varis recognises the key and doesn't charge you twice:

- **If the first call is still running,** Varis returns `202` with `"status": "in_progress"`. Wait for `retry_after_seconds`, and then retry with the same key.
- **If the first call failed,** Varis returns the same error again.
- **If the first call succeeded,** Varis returns `200` with `"replayed": true` and the same output, without charging again. Once the output is deleted, Varis returns `410` with `output_burnt` instead.

A retry returns the first call's `request_id`, not a new one.

If you reuse a key for a different service or a different input, Varis returns `409` with `conflict`.

A key stays reserved while its call runs and for 48 hours after the call ends. After that, the same key starts a new call, and you're charged for it.

<Callout title="How long Varis keeps an output">
Varis keeps each successful output, encrypted, so a retry after a lost response can still get it. Varis deletes it an hour after it's first returned, or 24 hours after the call finishes if it's never returned. If your agent needs the output for later, store it yourself.
</Callout>

## Handle errors

Every error has the same shape:

```json
{
  "error": {
    "code": "input_schema_violation",
    "message": "The input does not match the service's input schema.",
    "details": [{ "path": "/amount", "message": "must be number" }]
  },
  "request_id": "var_req_fc8e8702-6a7f-4f3f-9147-748936e5fee1"
}
```

| Status | Code | Charged | What to do |
| --- | --- | --- | --- |
| `400` | `input_schema_violation` | No | Fix the input to match `input_schema`. `details` lists each problem. |
| `400` | `invalid_request` | No | Fix the request, such as a missing `Idempotency-Key`. |
| `401` | `unauthorized` | No | Check the agent key, and check that the agent isn't revoked. |
| `402` | `insufficient_funds` | No | Show the `funding_url` to a person, and retry once they top up. If the error has `granted_credits`, retry straight away. |
| `403` | `forbidden` | No | The call is over the agent's spend limits. See [Spend limits](/use/spend-limits). |
| `404` | `not_found` | No | The service doesn't exist. Search again. |
| `409` | `service_not_invocable` | No | The service is disabled. Search for another one. |
| `409` | `conflict` | No | Use a new idempotency key. |
| `410` | `output_burnt` | No | The call succeeded, and its output is deleted. `completed_at` says when it ran. To run it again, use a new key. You're charged again. |
| `429` | `rate_limited` | No | Wait for the number of seconds in `Retry-After`, and then retry. |
| `500` | `internal_error` | No | Something went wrong on Varis's side. If the message says you weren't charged, retry with a new key. Otherwise, retry with the same key. |
| `502` | `provider_error` | No | The service failed, stopped reporting on a call that takes longer, or returned an output larger than 4 MB. Retry with a new key, or choose another service. |
| `502` | `schema_violation` | No | The service's output violates the I/O contract. Choose another service. |
| `504` | `timeout` | No | The service didn't answer within 30 seconds, or didn't finish within 24 hours. It may still have done the work. A retry with the same key returns this error again. A new key runs the service again. |

### Insufficient funds

If your balance can't cover a call, Varis returns `402` with a funding link:

```json
{
  "error": {
    "code": "insufficient_funds",
    "message": "The balance does not cover this call.",
    "shortfall_credits": 150,
    "funding_url": "https://usevaris.com/fund/t/abc123"
  },
  "request_id": "var_req_fc8e8702-6a7f-4f3f-9147-748936e5fee1"
}
```

Show `funding_url` to a person exactly as it is. Anyone who opens it can top up your balance, without signing in. After they pay, retry the call with the same idempotency key.

The link expires after 30 minutes. If it expires, the next retry returns a new one.

### Your first paid call

Each account gets a one-time $2 free credit for its first key action. If that action is a paid call your balance can't cover, and the call costs $2 or less, Varis adds the credit and returns the same `402` with `granted_credits`:

```json
{
  "error": {
    "code": "insufficient_funds",
    "message": "The available balance is too low for this request. As this is your first paid invocation, we've added a $2.00 credit to your balance. Retry this invocation with the same idempotency key to complete the request. When the task is done, ask the account owner to top up using the funding_url below. It expires in 30 minutes.",
    "shortfall_credits": 0,
    "funding_url": "https://usevaris.com/fund/t/abc123",
    "granted_credits": 20000
  },
  "request_id": "var_req_fc8e8702-6a7f-4f3f-9147-748936e5fee1"
}
```

Retry the call straight away with the same idempotency key, and show the `funding_url` to a person once the task is done.

A first call that costs more than $2 gets the plain `402` and no credit. Your first top-up adds the $2 instead.

## Limits on requests

Each agent can make 120 requests a minute to `POST /v1/invocations` and `GET /v1/invocations/{invocation_id}` together. Past that, Varis returns `429` with a `Retry-After` header.
